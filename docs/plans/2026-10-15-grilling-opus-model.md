# grilling スキルを Opus で動かす計画

## 目的

grilling スキルを使うときは、対話の最初から最後まで Opus で動かしたい。
grilling は設計ツリーの分岐をたどり、決定事項間の依存関係を解く作業であり、推論の深さが計画の質に直結するからだ。

ユーザー設定（`~/.claude/settings.json`）はすでに `"model": "opus"` になっている。
そのため問題になるのは、`/model` で別のモデルに切り替えたセッションで grilling を使う場合に限られる。

## 決定事項

### frontmatter の `model` だけでは足りない

SKILL.md の frontmatter に `model` を書くと、スキル起動時にモデルが切り替わる。
ただし公式ドキュメントによれば、この上書きは現在のターンにしか効かない。

> The override applies for the rest of the current turn and isn't saved to settings. The session model resumes when you send your next prompt.

grilling は質問を出してユーザーの返答を待つ対話型のスキルなので、2ターン目以降はセッションのモデルに戻る。
`context: fork` でサブエージェントとして動かせばモデルは固定できるが、サブエージェントは AskUserQuestion を使えず、ユーザーに質問できない。

### frontmatter で指定し、本文で毎ターン確認する

frontmatter に `model: opus` を書いたうえで、本文に確認手順を足す。
確認の内容は次のとおり。

- **確認のタイミング**：ユーザーの返答を受けた各ターンの冒頭
- **判定方法**：自分のモデル名に「Opus」が含まれるか
- **Opus でない場合**：質問を進めずに停止し、「`/model opus` に切り替えて、直前の返答をもう一度送ってください」と案内する

確認を起動時ではなく毎ターンにするのは、起動したターンは frontmatter の指定で必ず Opus になり、起動時の確認は常に通過してしまうからだ。
Opus 以外のモデルが動くのは2ターン目以降であり、スキル本文は会話に残り続けるので、そのモデルも確認手順を読める。
同じ理由で、停止後に `/grilling` を再実行する必要はなく、モデルを切り替えて返答を再送すれば続きから再開できる。
この方式なら、対話の途中で `/model` を切り替えた場合も検出できる。

警告だけ出して続ける案は採らない。
「必ず Opus で動かす」という要件に反し、2ターン目以降がセッションのモデルで進んでしまうからだ。

### モデルはエイリアス `opus` で指定する

フルモデルID（`claude-opus-5-5`）ではなくエイリアス `opus` を使い、判定もモデル名に「Opus」が含まれるかで行う。
`.claude/agents/*.md` の書き方と揃い、新しい Opus が出ても書き換えずに済む。
フルモデルIDを skills の `model` に書けるかは、ドキュメントから推測できるだけで明記されていない。

### 既存の未コミット変更は先に単独でコミットする

SKILL.md には、計画書の保存手順を追加した未コミットの変更がある。
今回の変更と目的が異なるので、この計画書のコミットより前に単独でコミットする。
メッセージは `feat: grillingスキルに計画書の保存手順を追加` とする。
`.claude/settings.json` の未コミット変更（`env` の追加）は今回の件と無関係なので触らない。

## 対象外

- `context: fork` によるサブエージェント化（AskUserQuestion が使えず、対話できないため）
- 推論の重い工程だけを Opus のサブエージェントに任せる構成
- フックによるモデルの強制（フックにはモデルを切り替える機能がない）
- `opus[1m]` への変更
- grilling 以外のスキルへの同様の指定

## リスク

- **起動したターンでモデル名を誤認する**：上書き中のモデルが自分のモデル名を正しく認識できない可能性がある。確認の対象を「ユーザーの返答を受けたターン」に限り、起動したターンは確認しないことで避ける。
- **上書きが無視される**：組織の `availableModels` で除外されたモデルや、auto mode で使えないモデルを指定すると、上書きは無視されてセッションのモデルが使われる。この場合も2ターン目の確認で停止するので、Opus 以外で質問が進むことはない。
- **意図して別のモデルで使いたい場合に止まる**：Sonnet などで grilling を使いたい場面でも停止する。「必ず Opus」という要件を優先し、この動作を受け入れる。
- **モデルが確認手順を守らない**：確認は本文の指示に頼っており、強制ではない。検証で停止することを確かめ、守られない場合は指示の位置や書き方を見直す。

## 検証方法

スキルの自動テストはないため、手動で確認する。

1. `/model sonnet` でセッションを切り替え、`/grilling テスト用の計画` を実行する。最初の質問が出ることを確認する。
2. 質問に返答し、質問を進めずに `/model opus` への切り替えを案内して止まることを確認する。
3. `/model opus` に切り替えて直前の返答を再送し、次の質問に進むことを確認する。
4. Opus のセッションで `/grilling` を実行し、計画書の保存まで一度も停止しないことを確認する。
